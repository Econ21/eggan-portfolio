ARIA

Satu chat operasional untuk dua perusahaan: laporan, keuangan, marketing, dan audit kode, masing-masing di jalurnya sendiri.

2perusahaan, terpisah penuh
~$0.08per laporan kerja (dulu $0,30)
214cek isolasi di setiap deploy
100%penulisan menunggu manusia
01

Mengapa dibuat

Tim membuka sepuluh dashboard untuk menjawab satu pertanyaan, dan menulis laporan mingguan secara manual. ARIA menjawab dalam satu chat dengan angka live, menyusun laporan, merencanakan konten, dan mengaudit kode. Dua perusahaan berbagi platform, jadi aturan terberatnya: masing-masing hanya pernah melihat datanya sendiri.

Dipakai olehStaf CAP dan MatchupSkills, dari marketing sampai keuangan, masing-masing dengan perannya.
02

Satu permintaan, langkah demi langkah

Klik sebuah langkah, atau tekan putar, untuk mengikuti satu permintaan nyata melewati sistem.

Langkah 1 / 7 · Team member

Sebuah permintaan

“Tulis laporan marketing minggu ini dan usulkan tiga postingan untuk minggu depan.”

trace
"Write this week's marketing report and suggest three posts for next week."

Langkah 2 / 7 · Session

Cek peran

Sesi admin menunjukkan siapa yang bertanya dan perannya. Peran marketing bisa membaca marketing dan konten; alat keuangan bahkan tidak ditawarkan ke model.

trace
const me = await requireStaff(req);                 // role: marketingconst tools = TOOLS.filter((x) => x.roles.includes(me.role));// finance_summary, payroll, users → not in the list at all

Langkah 3 / 7 · Tenant

Kunci perusahaannya

Perusahaan diambil dari login, bukan dari chat. Setiap query dalam permintaan ini dikunci ke data perusahaan itu. Prompt yang bilang “tunjukkan perusahaan lain” tidak mengubah apa pun.

trace
const tenant = tenantFor(me);                        // from the sessionconst db = scopedClient(tenant);                      // one schema, one storage prefixassertTenant(db, tenant);                             // refuses the sister company

Langkah 4 / 7 · Recall

Mengingat

ARIA mengambil laporan terakhir, content plan, dan catatan sebelumnya dari proyek ini, jadi laporan baru melanjutkan yang lama, bukan mulai dari awal.

trace
recall({ project: 'weekly-marketing' }) →  last_report: "w46", plan_rows: 18, open_actions: 3

Langkah 5 / 7 · Claude

Membaca angka live

Model memanggil alat baca: konten yang terbit minggu ini, jangkauan dan engagement, pendaftaran dari kampanye. Angka berasal dari database; model hanya menulis kata-kata di sekitarnya.

trace
→ query_metrics { range: "this_week", metrics: ["posts","reach","signups"] }← { posts: 11, reach: 48210, signups: 37, best: "REL-04" }

Langkah 6 / 7 · Tools

Draf, lalu menunggu

Laporan dan tiga ide postingan ditulis sebagai draf. Instruksi tetap di-cache, itulah sebabnya laporan kini sekitar delapan sen, bukan tiga puluh.

trace
→ report_save   { status: "draft" }→ content_plan  { add: 3, status: "proposed" }      // not published

Langkah 7 / 7 · Approval

Manusia menyetujui

Apa pun yang keluar dari sistem, seperti email, postingan, atau perubahan status, masuk antrean persetujuan. Orang dengan peran yang tepat menekan setuju; aksi dan penyetujunya dicatat.

postgresql
insert into approvals (tenant, action, payload, requested_by)values ($1, 'publish_post', $2, $3);       -- waits-- on approve: run action, write audit_log (who, what, when)

04

Kode

Dua bagian yang paling menentukan di agent ini.

Setiap panggilan alat melewati gerbang yang sama: peran, perusahaan, lalu persetujuan untuk apa pun yang menulis.

aria/run_tool.jsjavascript
export async function runAriaTool(call, session) {  const tool = REGISTRY[call.name];  if (!tool || !tool.roles.includes(session.role)) return deny('not allowed for this role');   const input = tool.schema.parse(call.input);           // reject bad arguments  const db = scopedClient(session.tenant);              // company comes from login   if (tool.writes) {    const id = await queueApproval(db, { tool: call.name, input, by: session.user });    return { status: 'waiting_for_approval', id };  }  const result = await tool.run(db, input);  await audit(db, session, call.name, input);  return redact(result);                                // no keys, no personal data}

Bagian dari suite isolasi yang jalan di setiap deploy: perusahaan A tidak boleh menjangkau perusahaan B dengan cara apa pun.

aria/isolation.test.jsjavascript
for (const [me, other] of [[CAP, MS], [MS, CAP]]) {  const db = scopedClient(me);  await expectDenied(() => db.schema(other.schema).from('users').select('*'));  await expectDenied(() => db.storage.from(other.bucket('files')).list());  await expectDenied(() => runAriaTool(    { name: 'query_metrics', input: { tenant: other.id } }, sessionOf(me)));}
05

Data dan pengaman

Yang disimpan

  • conversations · projectspercakapan dikelompokkan per proyekper perusahaan
  • reportslaporan kerja harian, mingguan, bulananarsip dengan status persetujuan
  • approvalsaksi tertunda menunggu manusiasampai disetujui atau ditolak
  • audit_logsiapa bertanya apa, alat apa jalan, siapa menyetujuidisimpan untuk peninjauan

Yang menjaganya aman

  • Perusahaan dari loginTenant tidak pernah dibaca dari chat, jadi tidak ada prompt yang bisa berpindah perusahaan.
  • Alat sesuai peranAlat yang tidak boleh dipakai suatu peran tidak pernah ditawarkan ke model.
  • Penulisan menungguEmail, postingan, dan perubahan status perlu persetujuan manusia.
  • Tidak ada rahasia di konteksKunci dan data pribadi dibuang dari hasil alat sebelum dilihat model.
