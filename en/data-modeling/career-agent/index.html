Career Agent

Finds jobs, writes the documents and tracks every application until the offer.

10stages per application
2models: small for chat, strong for documents
$0.12for a complete tailored CV request
0facts the agent may invent
01

Why it exists

People looking for work send dozens of applications, lose track of them and send the same generic CV everywhere. The Career Agent keeps one evidence bank of what the person really did, tailors every CV and letter from it, and keeps an honest tracker from “saved” to “hired”.

Used byJob seekers on MatchupSkills, from students looking for an internship to professionals changing field.
02

One request, step by step

Click a step, or press play, to follow one real request through the system.

Step 1 / 7 · Job seeker

A job ad comes in

The job seeker pastes an ad for a data analyst role and asks for a tailored CV.

trace
"Here's a Data Analyst ad (Rotterdam, hybrid). Tailor my CV and save it."

Step 2 / 7 · State

Load the state

The agent reads the profile, the evidence bank and the tracker, so it knows what was already sent and what the person can prove.

trace
career_get_state() → { profile, evidence: 41 items, applications: 37,  duplicates: ["same company, other role (applied 9 days ago)"] }

Step 3 / 7 · Tools

Save and score the job

The job is saved and scored against the evidence: required skills found, missing and risky. Here the fit is 70/100 and the agent says which gap matters.

trace
save_jobs([{ title: "Data Analyst", city: "Rotterdam" }])score_fit → { score: 70, band: "risky",  matched: ["SQL", "Power BI", "stakeholders"],  missing: ["dbt"], note: "say SQL pipelines, not dbt" }

Step 4 / 7 · Router

The router steps in

The small, fast model starts writing the CV. The router sees a document call and stops it: documents are written by the stronger model. The small model’s attempt is discarded, not shown.

trace
if (engine.small && calls.some(isDocumentCall)) {  usage.void(res);                // not shown, not billed to the user  engine = STRONG;                 // replay the same turn  continue;}

Step 5 / 7 · Tools

Write the documents

The strong model writes the CV from the evidence bank only. Every line is mapped to an evidence item; anything that cannot be mapped is removed. The CV is rendered and must fit one page.

trace
build_package({ job, cv_master }) →  claims: 14 · mapped to evidence: 14 · removed: 0  render: CV.pdf (1 page ✓) · CV.docx · letter.pdf (1 page ✓)

Step 6 / 7 · Tracker

Update the tracker

The application moves to “ready” and the timeline gets an entry. Moving it to “applied” needs the job seeker’s own click: the agent never changes a status on its own.

postgresql
update applications set stage = 'ready' where id = $1 and owner = $2;insert into application_events (application, kind, note)values ($1, 'package_built', 'CV + letter, 1 page each');-- 'applied' only via the owner's confirm button

Step 7 / 7 · Documents

Files are delivered

The job seeker gets a PDF and an editable Word file through short-lived private links. Cost of the whole request: $0.12, of which 92% is the CV itself.

trace
turns: haiku 0.0044 · 0.0027 · 0.0025 (void) · sonnet 0.1103total: $0.120  ·  links expire after 1 hour

04

Code

Two pieces that carry the most weight in this agent.

A CV line survives only if it points to something the person really did.

career/evidence_guard.jsjavascript
export function keepProvenClaims(draft, evidence) {  const byId = new Map(evidence.map((e) => [e.id, e]));  const kept = [], removed = [];  for (const line of draft.lines) {    const ok = line.evidence?.length &&      line.evidence.every((id) => byId.has(id)) &&      numbersMatch(line.text, line.evidence.map((id) => byId.get(id)));    (ok ? kept : removed).push(line);  }  return { ...draft, lines: kept, removed };   // removed lines are logged, never shown}

Chat runs on the small model; any document call is replayed on the strong one.

career/router.jsjavascript
const isDocumentCall = (c) =>  c.name === 'build_package' || Boolean(c.input?.cv_master); for (let round = 0; round < MAX_ROUNDS; round++) {  const res = await model(engine).send(messages, tools);  usage.add(engine.id, res.usage);  const calls = res.content.filter((b) => b.type === 'tool_use');  if (engine === SMALL && calls.some(isDocumentCall)) {    usage.void(res); engine = STRONG; continue;  }  if (!calls.length) return res;  messages.push(res, await runTools(calls, ctx));}
05

Data and guardrails

What it keeps

  • applicationscompany, role, stage (10), fit scoreowner’s own tracker
  • application_eventstimeline: every change with who did itfull history
  • evidenceroles, results, numbers the person can proveedited by the owner
  • documentsCV and letter versions per applicationprivate storage, signed links
  • text_i18ntranslations of the owner’s own notesper account

What keeps it safe

  • Evidence or nothingA claim without evidence never reaches a document.
  • Humans move the statusThe agent may propose “applied” or “rejected”; only the owner confirms it.
  • One company, one shotDuplicates are flagged before a second application to the same company.
  • Private filesCVs live in private storage and open through links that expire within the hour.
