Market desk

A personal market desk that reads the market, proposes trade setups and grades itself later. It never places a trade.

3timeframes read together: 1 h, 4 h, 1 day
4analysts compared: one rule-based, three AI
100%of setups graded against real prices
0trades placed
01

Why it exists

Market opinions are cheap; tracked opinions are rare. The desk writes every idea down as a precise setup (where to enter, where it is wrong, where to take profit) before the outcome is known, then checks the real prices afterwards. Over time it learns which kinds of setups deserve trust and which do not.

Used byMe. It is a personal research tool inside Northstar, my planning app.
02

One request, step by step

Click a step, or press play, to follow one real request through the system.

Step 1 / 7 · Scheduler

A new packet

On a fixed schedule the desk builds a packet: one snapshot of the market that every analyst will read.

trace
packet { slot: "2026-11-21T08:00Z", assets: ["BTC","ETH","SOL", …],         macro: { dxy, us10y, fear_greed }, memory: {…} }

Step 2 / 7 · Market data

Fetch prices

Candles for three timeframes come from public market data, plus funding rates for crypto. Missing or stale data marks the asset as “no read” instead of guessing.

trace
candles("BTC", "1h", 500) · candles("BTC", "4h", 500) · candles("BTC", "1d", 400)if (ageMinutes(last) > 2 * tfMinutes) asset.read = null;   // no stale reads

Step 3 / 7 · Indicators

Compute indicators

For each timeframe: 20- and 50-period averages, RSI, MACD, average true range (how much price usually moves), and the nearest support and resistance levels.

trace
d: { ema20: 94120, ema50: 89870, rsi14: 61, atr14: 2840, trend_score: 0.6 }h: { rsi14: 55, macd_hist_rising: true, trend_score: 0.4 }h: { trend_score: -0.2 }

Step 4 / 7 · Rule engine

The rule engine decides a stance

The three trend scores are weighted 50 / 30 / 20 (day, 4 hours, hour) into one number. That gives a stance, long, short or wait, and a setup with an entry zone, a stop placed by volatility and two targets. No AI in this step.

trace
composite = 0.5*0.6 + 0.3*0.4 + 0.2*(-0.2) = 0.38  → stance: longsetup { type: "trend_pullback", entry: 93.k–94.k, stop: 91.k,        tp1: 97.k, tp2: 101.k, rr: 1.6 }

Step 5 / 7 · AI analysts

AI analysts add their view

Three AI analysts read the same packet and write their own setups with reasons. Each setup is validated: the stop must be on the losing side, targets on the winning side, and the reward at least 1.2 times the risk. Invalid setups are rejected, not fixed.

trace
cleanSetup(ai) → rejected: "stop above entry for a long"cleanSetup(ai) → ok { type: "breakout", rr: 2.1, confidence: 0.55 }

Step 6 / 7 · Grader

Grade with real prices

Later, every setup is replayed against the candles that actually came. Did price reach the entry? Then which came first: the stop or a target? The result is written in R, the profit or loss measured in units of the risk taken.

trace
grade(setup, candlesAfter) → { outcome: "tp1", r: +1.6, hours: 31 }grade(setup2, candlesAfter) → { outcome: "stopped", r: -1.0, hours: 9 }

Step 7 / 7 · Journal

Memory feeds the next packet

Win rate and average R per setup type and per analyst go into the next packet, so analysts see which of their ideas actually worked. The journal keeps every call with its outcome.

trace
memory.trend_pullback = { n: 46, win: 0.54, avgR: +0.31 }memory.mean_reversion = { n: 29, win: 0.38, avgR: -0.12, note: "skip against the daily trend" }

04

Code

Two pieces that carry the most weight in this agent.

The rule engine: weights three timeframes into one score and builds a setup with a volatility-based stop.

markets/signal.jsjavascript
const WEIGHT = { '1d': 0.5, '4h': 0.3, '1h': 0.2 }; export function composite(tf) {  let s = 0, w = 0;  for (const [k, wt] of Object.entries(WEIGHT))    if (tf[k]?.trend_score != null) { s += tf[k].trend_score * wt; w += wt; }  return w ? s / w : 0;} function setup({ direction, entryLow, entryHigh, stop, targets }) {  const entry = (entryLow + entryHigh) / 2, risk = Math.abs(entry - stop);  if (!risk) return null;  const sign = direction === 'long' ? 1 : -1;  let [tp1, tp2] = targets;  if (tp1 == null || (tp1 - entry) * sign < 1.2 * risk) tp1 = entry + sign * 1.5 * risk;  if (tp2 == null || (tp2 - tp1) * sign <= 0) tp2 = entry + sign * 3 * risk;  return { direction, entryLow, entryHigh, stop, tp1, tp2,           rr: +(Math.abs(tp1 - entry) / risk).toFixed(2) };}

The grader walks forward through real candles. If one candle touches both the stop and a target, it counts as a loss: the honest assumption.

markets/grade.jsjavascript
export function grade(s, candles) {  const long = s.direction === 'long';  let entered = false;  for (const c of candles) {    if (c.time > s.expires_at) return { outcome: entered ? 'expired' : 'not_triggered', r: 0 };    if (!entered) { entered = c.low <= s.entryHigh && c.high >= s.entryLow; if (!entered) continue; }    const hitStop = long ? c.low <= s.stop : c.high >= s.stop;    const hitTp1  = long ? c.high >= s.tp1 : c.low <= s.tp1;    if (hitStop) return { outcome: 'stopped', r: -1 };          // stop first if both    if (hitTp1)  return { outcome: hitsTp2(s, c) ? 'tp2' : 'tp1', r: rOf(s, hitsTp2(s, c)) };  }  return { outcome: 'open', r: null };}
05

Data and guardrails

What it keeps

  • packetsone market snapshot per slotkept for replay
  • reportseach analyst’s written viewkept
  • calls (setups)entry, stop, targets, reason, sourceappend only, written before the outcome
  • gradesoutcome and R per callfeeds the memory

What keeps it safe

  • Analysis onlyThere is no exchange account with trading rights anywhere in the system.
  • No hindsightA call is stored before its outcome is known and can never be edited.
  • Sane numbers onlyAI setups with a stop on the wrong side or a poor reward are rejected.
  • Stale data is no dataIf prices are late, the asset is skipped instead of read from old candles.
