04 · CAP · MatchupSkills ops · in productie

ARIA

Eén ops-chat voor twee bedrijven: rapporten, financiën, marketing en code-audits, elk in zijn eigen baan.

2bedrijven, volledig gescheiden
~$0.08per werkrapport (was $0,30)
214isolatiechecks bij elke deploy
100%van de schrijfacties wacht op een mens
01

Waarom hij bestaat

Het team opende tien dashboards voor één vraag en schreef weekrapporten met de hand. ARIA antwoordt in één chat met de live cijfers, maakt het rapport, plant content en controleert code. Twee bedrijven delen het platform, dus de strengste regel is dat elk alleen zijn eigen data ziet.

Gebruikt doorMedewerkers van CAP en MatchupSkills, van marketing tot financiën, elk met een eigen rol.
02

Eén verzoek, stap voor stap

Klik op een stap, of druk op afspelen, om één echt verzoek door het systeem te volgen.

Stap 1 / 7 · Team member

Een verzoek

“Schrijf het marketingrapport van deze week en stel drie posts voor volgende week voor.”

trace
"Write this week's marketing report and suggest three posts for next week."

Stap 2 / 7 · Session

Rolcheck

De adminsessie zegt wie vraagt en welke rol hij heeft. Een marketingrol mag marketing en content lezen; financiële tools worden het model niet eens aangeboden.

trace
const me = await requireStaff(req);                 // role: marketingconst tools = TOOLS.filter((x) => x.roles.includes(me.role));// finance_summary, payroll, users → not in the list at all

Stap 3 / 7 · Tenant

Het bedrijf vastzetten

Het bedrijf komt uit de login, nooit uit de chat. Elke query in dit verzoek is vastgepind op de data van dat bedrijf. Een prompt die zegt “laat het andere bedrijf zien” verandert niets.

trace
const tenant = tenantFor(me);                        // from the sessionconst db = scopedClient(tenant);                      // one schema, one storage prefixassertTenant(db, tenant);                             // refuses the sister company

Stap 4 / 7 · Recall

Herinneren

ARIA haalt het vorige rapport, het contentplan en eerdere notities uit dit project, zodat het nieuwe rapport verdergaat in plaats van opnieuw te beginnen.

trace
recall({ project: 'weekly-marketing' }) →  last_report: "w46", plan_rows: 18, open_actions: 3

Stap 5 / 7 · Claude

De live cijfers lezen

Het model roept leestools aan: content van deze week, bereik en engagement, aanmeldingen uit campagnes. De cijfers komen uit de database; het model schrijft alleen de woorden eromheen.

trace
→ query_metrics { range: "this_week", metrics: ["posts","reach","signups"] }← { posts: 11, reach: 48210, signups: 37, best: "REL-04" }

Stap 6 / 7 · Tools

Concept, dan wachten

Het rapport en drie postideeën worden als concept geschreven. De vaste instructies zijn gecachet, daarom kost een rapport nu ongeveer acht cent in plaats van dertig.

trace
→ report_save   { status: "draft" }→ content_plan  { add: 3, status: "proposed" }      // not published

Stap 7 / 7 · Approval

Een mens keurt goed

Alles wat naar buiten gaat, zoals een e-mail, post of statuswijziging, gaat naar een goedkeuringswachtrij. Iemand met de juiste rol keurt goed; actie en goedkeurder worden gelogd.

postgresql
insert into approvals (tenant, action, payload, requested_by)values ($1, 'publish_post', $2, $3);       -- waits-- on approve: run action, write audit_log (who, what, when)

04

Code

Twee stukken die in deze agent het zwaarst wegen.

Elke toolcall gaat door dezelfde poort: rol, bedrijf, en goedkeuring voor alles wat schrijft.

aria/run_tool.jsjavascript
export async function runAriaTool(call, session) {  const tool = REGISTRY[call.name];  if (!tool || !tool.roles.includes(session.role)) return deny('not allowed for this role');   const input = tool.schema.parse(call.input);           // reject bad arguments  const db = scopedClient(session.tenant);              // company comes from login   if (tool.writes) {    const id = await queueApproval(db, { tool: call.name, input, by: session.user });    return { status: 'waiting_for_approval', id };  }  const result = await tool.run(db, input);  await audit(db, session, call.name, input);  return redact(result);                                // no keys, no personal data}

Deel van de isolatiesuite die bij elke deploy draait: bedrijf A mag bedrijf B op geen enkele manier bereiken.

aria/isolation.test.jsjavascript
for (const [me, other] of [[CAP, MS], [MS, CAP]]) {  const db = scopedClient(me);  await expectDenied(() => db.schema(other.schema).from('users').select('*'));  await expectDenied(() => db.storage.from(other.bucket('files')).list());  await expectDenied(() => runAriaTool(    { name: 'query_metrics', input: { tenant: other.id } }, sessionOf(me)));}
05

Data en vangrails

Wat hij bewaart

  • conversations · projectsgesprekken gegroepeerd per projectper bedrijf
  • reportsdagelijkse, wekelijkse en maandelijkse werkrapportenarchief met goedkeuringsstatus
  • approvalsacties die op een mens wachtentot goed- of afgekeurd
  • audit_logwie wat vroeg, welke tool draaide, wie goedkeurdebewaard voor controle

Wat hem veilig houdt

  • Bedrijf uit de loginDe tenant komt nooit uit de chat, dus geen prompt kan van bedrijf wisselen.
  • Tools per rolEen tool die de rol niet mag gebruiken, wordt het model nooit aangeboden.
  • Schrijven wachtE-mails, posts en statuswijzigingen vragen goedkeuring van een mens.
  • Geen geheimen in de contextSleutels en persoonsgegevens worden uit toolresultaten gehaald vóór het model ze ziet.
